「多 Agent」在行业里很容易被讲成噱头：角色越多越先进。生产里真正有价值的是 **职责隔离、最小权限、可观测、可回退**。本文整理企业 AI 中台常见的四层协同架构，以及和单 Agent、LangGraph 的对应关系 — 来自我在 DHLink 多智能体中台项目中的架构实践与方案沉淀。

### 一、为什么单 Agent 撑不住复杂业务

单 Agent 适合：FAQ、单工具调用、短链路问答。

复杂任务（串联检索、调多个系统、出报告、过合规）塞进一个 Prompt 会导致：

- Prompt 膨胀难维护；
- 工具权限无法最小化；
- 某步失败无法局部重试；
- 结果难追溯、难评测。

**多 Agent 的核心不是角色多，而是把规划、检索、执行、审核拆开。**

### 二、四层协同架构（总览）

```text
用户 / 业务系统
      ↓
API 网关（鉴权、限流、熔断、审计）
      ↓
┌──────────────────────────────────────────────┐
│  规划 Agent    意图解析、任务拆解、流程编排     │
│       ↓                                      │
│  执行 Agent    工具调用、子任务汇总             │
│       ↕                                      │
│  检索 Agent    混合检索、Rerank、权限过滤       │
│       ↓                                      │
│  审核 Agent    格式、证据、合规、安全            │
└──────────────────────────────────────────────┘
      ↓
能力层：RAG、Function Call 注册、Prompt 模板库
      ↓
LLMOps：链路追踪、Token/耗时、评测集、告警降级
      ↓
基础设施：LLM、Qdrant、Redis、消息队列
```

### 三、各层职责

| Agent | 输入 | 输出 | 关键决策 |
|-------|------|------|----------|
| 规划 | 用户自然语言 | 结构化任务计划 JSON | 复杂拆解用 CoT，独立规划符合单一职责 |
| 执行 | 任务计划 | 工具结果、汇总草稿 | ReAct 循环在服务端，模型不直连外部 API |
| 检索 | 查询词 + 权限上下文 | 带引用的文档片段 | 混合检索 + 阈值拒答 |
| 审核 | 草稿答案 | 通过 / 驳回 / 人工 | 高风险字段不走模型终审 |

### 四、编排模式：顺序、并行与审核门

```text
顺序：规划 → 检索 → 执行 → 审核 → 返回

并行：规划拆出子任务 A（查库）与 B（算费）并行，执行 Agent 汇总

审核门：写库、发布、对外回复 — 必须过审核 Agent 或人工 interrupt
```

和 LangGraph 的对应：**每个 Agent 角色可映射为一个 Node（或子图）**，边表达依赖与条件分支。

### 五、死循环与冲突防护

**死循环**

- `max_iterations` 与最大调用深度；
- 每次调用带 `traceId`、父任务 ID；
- 检测 `A→B→A` 重复链路透传熔断；
- 超限返回「已完成摘要 + 待人工项」。

**任务冲突**

- 工具读写分级，默认只读；
- 写操作显式确认或串行队列；
- 幂等键防重试双写。

### 六、LLMOps 与评测

建议同时监控：

| 指标 | 含义 |
|------|------|
| 任务完成率 | 端到端是否达成用户目标 |
| 工具正确率 | 是否调对工具、参数合法 |
| 幻觉率 / 拒答正确率 | 无证据时是否乱答 |
| P95 响应耗时 | 体验与成本 |
| Token / 单次成本 | 预算与降级依据 |

指标口径应基于业务验收集与抽检，并在方案评审里对齐定义。

### 七、落地节奏（务实路线）

1. **阶段一**：单 Agent + RAG + 审核规则（够用就不拆）。
2. **阶段二**：检索与执行拆分，工具权限分离。
3. **阶段三**：规划 Agent + LangGraph 编排 + Checkpoint。
4. **阶段四**：全链路 LLMOps 与 A/B Prompt。

早期「问答 Agent + 审核规则」往往比四个 GPT 角色互聊更稳。

### 八、小结

> 企业多 Agent 是工程上的**控制流与权限架构**，不是聊天室里多几个 Bot。四层图、审核门和评测指标，才是架构设计里真正要交付的东西。

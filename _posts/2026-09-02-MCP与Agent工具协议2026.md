MCP（Model Context Protocol）在 2026 年已成为 Agent 工具生态的重要标准。很多人把 MCP 和 Function Calling 当成两套完全不同的技术，团队讨论时也容易层级混乱。本文用一层协议栈把关系说清楚，并给出我在业务产品与研发效能两条线上的分工实践。

### 一、三层模型：在正确的层级上设计

```text
┌─────────────────────────────────────┐
│  应用 / Host（Cursor、Nest 服务）    │
│  编排循环、权限、审计、UI              │
└─────────────────────────────────────┘
              ↓ 调用
┌─────────────────────────────────────┐
│  协议层：MCP / 厂商 Function Calling   │
│  统一的 tools / resources 描述与传输   │
└─────────────────────────────────────┘
              ↓ 执行
┌─────────────────────────────────────┐
│  业务能力：查库、发 HTTP、读 Figma…    │
└─────────────────────────────────────┘
```

- **Function Calling**（OpenAI 等）：模型输出 `tool_calls`，宿主应用执行函数。
- **LangChain `@tool`**：在 TS/Python 里声明工具，语义上仍是「模型选工具 + 宿主执行」。
- **MCP**：跨进程/跨服务的标准协议，Host 连接 MCP Server 暴露的 tools 与 resources，适合 **IDE、设计稿、数据库** 等异构能力统一接入。

若生产里已用 LangChain Tool，可以这样理解：**语义等同 Function Calling；MCP 是把工具面从单一应用扩展到可插拔 Server 的协议层。**

### 二、MCP 解决的真实痛点

| 痛点 | 没有 MCP 时 | 有 MCP 时 |
|------|-------------|-----------|
| 工具散落 | 每个 Host 手写 Figma/Git/DB 适配 | Server 一次实现，多 Host 复用 |
| 权限边界 | Prompt 里塞 API Key 风险高 | Server 侧鉴权，模型只见 schema |
| 研发协同 | 前端 Agent 与设计工具耦合 | 设计侧提供 MCP Server，研发侧只连协议 |

团队资产库里「CLI + Figma/MasterGo MCP」类实践，核心思路是：**把可复用能力协议化，而不是把 Prompt 写长**。

### 三、最小 MCP Server 的设计要素

落地一个 MCP Server，至少需要想清楚四件事：

1. **Server 暴露什么** — 例如 `parse_playlist(url)`、`search_docs(query)`。
2. **Schema** — 参数类型、必填项、错误返回格式。
3. **Host 怎么连** — stdio / SSE，配置在 Cursor `mcp.json` 或自有 Host。
4. **安全** — 只读默认、写操作二次确认、路径白名单。

### 四、与 Nest 全栈后端的组合

Web 产品里的 Agent 通常仍是 **REST + 服务端 Tool 注册表**，不必强行把所有 API 都 MCP 化。我的分工习惯：

- **对用户对话的 Tool** — Nest Provider 内注册，走业务鉴权与限流。
- **对研发效能的 Tool** — Figma、仓库、CI，用 MCP Server 给 Cursor / 内部 CLI。

这样既能覆盖 **B 端业务 Agent** 与 **研发 Agent** 两条线，又避免「全线 MCP」的过度设计。

### 五、安全清单

1. 工具白名单，禁止模型自选 HTTP 任意 URL。
2. 参数服务端校验（DTO / zod），不信任模型 JSON。
3. 敏感字段脱敏后再进上下文。
4. 写操作：发布、删库、支付 — **审核门或人工确认**，不交给单 Agent 闭环。

### 六、小结

MCP 不是替代 ReAct 的新范式，而是 **工具供给的标准化接口**。工程上值得坚持的分工是：能说清 Host / Protocol / Capability 三层，业务 Tool 在 Nest、效能 Tool 走 MCP。

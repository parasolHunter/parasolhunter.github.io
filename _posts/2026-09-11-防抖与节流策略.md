搜索联想、窗口 resize、滚动加载、按钮连点 — 这些场景如果每次事件都触发完整逻辑，会造成多余计算与接口压力。**防抖（debounce）** 和 **节流（throttle）** 是前端最常用的两种频率控制手段。

共同点：在 `delay` 时间窗口内，多次触发最终只执行有限次（防抖通常 1 次，节流按间隔 1 次）。

> 以下实现用于理解原理；生产环境可优先使用 Lodash、`@vueuse/core`、`ahooks` 等经过边界测试的版本，并结合框架生命周期正确清理定时器。

### 一、怎么选

| 策略 | 行为 | 典型场景 |
|------|------|----------|
| **防抖** | 停止触发后等待 `delay` 再执行；连续触发会重置计时 | 搜索框输入、表单校验 |
| **节流** | 每 `delay` 最多执行一次 | scroll、mousemove、拖拽 |

### 二、防抖实现

参数说明：

- `fn`：要执行的函数
- `delay`：等待毫秒数
- `immediate`：`true` 时首次触发立即执行，之后 `delay` 内不再执行；`false` 时延迟到最后一次触发后执行

```javascript
function debounce(fn, immediate = false, delay = 300) {
  let timeout;
  return function (...args) {
    const ctx = this;
    if (timeout) clearTimeout(timeout);
    if (immediate) {
      const callNow = !timeout;
      timeout = setTimeout(() => { timeout = null; }, delay);
      if (callNow) fn.apply(ctx, args);
    } else {
      timeout = setTimeout(() => fn.apply(ctx, args), delay);
    }
  };
}
```

**效果**：`delay` 内连续触发，只执行第一次（immediate）或最后一次（默认）。

**React 注意**：在 `useEffect` 或 `useMemo` 中创建 debounced 函数，避免每次 render 新建导致定时器失效；组件卸载时 `clearTimeout`。

### 三、节流实现

参数说明：

- `timeStamp`：`true` 使用时间戳版（推荐）；`false` 使用定时器版
- `delay`：间隔毫秒数

**时间戳版**：第一次立即执行，之后在 `delay` 窗口内忽略后续触发。

```javascript
export function throttle(fn, timeStamp = true, delay = 300) {
  let previous = 0;
  let timeout;
  return function (...args) {
    const ctx = this;
    if (timeStamp) {
      const now = Date.now();
      if (now - previous > delay) {
        fn.apply(ctx, args);
        previous = now;
      }
    } else {
      if (!timeout) {
        timeout = setTimeout(() => {
          timeout = null;
          fn.apply(ctx, args);
        }, delay);
      }
    }
  };
}
```

**效果**：`delay` 内多次触发同一事件，只执行一次，直到下一个窗口。

### 四、Vue / React 中的用法示例

**Vue 3**

```javascript
import { debounce } from './utils';

const onInput = debounce((e) => {
  fetchSuggestions(e.target.value);
}, 400);
```

**React**

```javascript
const debouncedSearch = useMemo(
  () => debounce((q) => fetchApi(q), 400),
  []
);
useEffect(() => () => debouncedSearch.cancel?.(), [debouncedSearch]);
```

### 五、别滥用

- 需要**保留每一次**中间状态（如拖拽轨迹）→ 不用 debounce，考虑 throttle 或 `requestAnimationFrame`。
- 服务端接口本身有 rate limit → 前端 throttle + 后端限流双重保护。
- SSR 环境无 `window` 事件 → 仅在客户端挂载后绑定。
